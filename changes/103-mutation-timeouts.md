**Every mutation shard is run to its end, and a Timeout of it counts as killed only when it is a proven hang** (agbossjs/mongodb#103, written agbossjs/agboss#103 as the changelog check reads it; agbossjs/agboss#1367): a Timeout counted as killed and hid survivors in the `leases` and `migrations` shards. The conformance suites of a shard are chosen by `MUTATION_SHARD` (a `testNamePattern` overrode Stryker's per-test filter on every mutant, so a mutant covered by two tests ran them all), `timeoutFactor` is 3 and each shard has its own `timeoutMS` (`scripts/stryker-timeouts-ms.mjs`, 120 s at least), and `scripts/stryker-timeouts.mjs` (the core's, as it is) fails a shard on a Timeout the clock ended, a RuntimeError or a CompileError that is not in `scripts/stryker-proven-hangs.json`, and on an entry no mutant matches; a Timeout of Stryker's hit limit (a loop that does not end) is counted, not listed. The cache of a shard's incremental run is keyed by the limits, so a change of them runs every shard cold. Two more shards (`a2a-direct`, `checkpoints`), the shards' own test-infrastructure fixes (a mutation run shortens the servers' transaction lifetime to 10 s, so a mutant killed inside a transaction does not hold the next one's database for a minute; the `pauses` and `money` shards run two mutants at a time), and the tests that kill what the first complete runs found; no store behaves differently. Two stop checks that were read once outside their loop (the liveness watch's and the queue watch's reopen) are read in it.
