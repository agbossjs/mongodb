**A Stryker Timeout of the clock that is not listed is run again alone, the list holds one hang, and a mutation run puts the transaction lifetime back** (agbossjs/mongodb#103, written agbossjs/agboss#103 as the changelog check reads it; agbossjs/agboss#1367): 12 of the 13 entries of `scripts/stryker-proven-hangs.json` were Killed in 0.3-11 s when run alone and in both runs of CI at concurrency 1; which static mutants end as Timeouts moves from run to run on a loaded runner, so the list only hid it. They are deleted. `scripts/stryker-timeouts.mjs --rerun` (the core's, with its helper `scripts/stryker-rerun.mjs`, byte for byte; wired into `ci.yml` and `mutation-nightly.yml` for every shard) runs each unlisted Timeout of the clock again alone in a fresh Stryker process: Killed passes with a note; Survived, a second Timeout, an error or a missing mutant fails. The one entry left, `close-bounded.ts` `missingDriverInternal` `true`, ran to the limit on CI in 2 of 2 runs (330 s and 341 s, the whole shard takes 20-30 s) and never alone, locally or in a Linux container (5 of 5 Killed in 17-29 s): its proof says so, and that its cause is open. `npm run test:mutation` goes through `scripts/mutation-run.mjs`, which sets every member's `transactionLifetimeLimitSeconds` to 10 s for the run (it was set by the tests' global setup and never put back) and sets each back to what it was when the run ends, whatever its outcome. Test-only and CI changes; no product behaviour changes; no migration.
